SME-I 前端与队友接口对接清单

本文为依据说明书建立的联调契约草案。说明书明确业务功能与分期，没有规定 HTTP 路径、JSON 字段或接口框架。下列约定需要与你的后端队友确认；如果最终采用云函数，保持前端业务方法与返回对象稳定，在 services 层完成适配。

你负责：页面、组件、CSS、表单校验、交互状态、调用接口和展示结果。队友负责：认证、数据持久化、账单解析、去重、自动分类、正式指标计算、模型调用、预警规则执行、备份和文件生成。

MVP 对接采集、录账、基础分类/成本/商品、分析和智能问答。OCR、主动预警、高级成员管理、备份与导出按说明书后续阶段预留。基础身份与数据隔离是 MVP 运行前提。当前工程是 Web，不等于已完成说明书一期微信小程序。

**公共协议先固定。** 所有组件只调用 `src/services/api` 中的领域方法。真实接口尚未完成时，通过显式注入的 Mock transport 开发页面；真实网络失败不回退成模拟成功。

| 约定 | 本草案选择 | 对接注意 |
| --- | --- | --- |
| API 前缀 | `/api/v1`，可通过配置替换 | 路径是草案；不要在每个组件中拼 URL |
| 成功返回 | `{ data, meta }` | meta 包含 requestId，可含 dataVersion、snapshotId、generatedAt；其他元数据需另行商定 |
| 失败返回 | `{ error: { code, message, fieldErrors }, meta }` | HTTP 状态与业务 code 一起保留；不将后端 HTML 错误页直接显示给用户 |
| 金额 | `amountMinor: "12850"` 表示 ¥128.50 | 正值分字符串；direction 独立；服务端精确计算 |
| 比率 | ratio 类型用小数，如 `"0.36"` 表示 36% | percentage_point 类型用点数，如 `"-3.1"` 表示下降 3.1 个百分点 |
| 日期 | 业务日期 `YYYY-MM-DD`；事件时间 ISO 8601 | 指标范围采用 startDate 含、endDate 不含，时区明确 |
| 分页 | 查询 `cursor`、`limit`；返回 `{ items, nextCursor, total? }` | 首页不传 cursor；nextCursor 为 null 表示末页；cursor 是不透明游标，前端不能按数字解释 |
| 主体上下文 | `X-Business-Id` | 服务端必须结合登录身份验证，不能信任前端 ID |
| 身份 | 登录方式由平台确定；客户端注入 token 获取回调 | 密钥、长期令牌不能配置为 VITE_ 环境变量 |
| 写入幂等 | `Idempotency-Key` | 一次用户操作一个 key；同操作重试复用；新操作重新生成 |
| 并发修改 | `If-Match` 携带服务端 revision | 版本不符返回冲突，前端提示刷新/核对，不强行覆盖 |
| 取消与超时 | AbortSignal 与超时独立处理 | 取消浏览器请求不等于取消后台任务；超时不等于未写入 |
| 后端任务 | queued、running、succeeded、failed、cancelled | 通用 Job 的业务阶段放 `stage`，进度为可空 progress；业务实体另有自身 status，不能混用 |
| 错误反馈 | 401、403、404、409/412、422、429、5xx 等 | 具体 code 与 HTTP 映射要一起确认 |

如使用 Cookie 会话，双方另行确定凭据、同源/跨域与防伪请求策略；不要同时混用互相矛盾的会话模式。当前调用层的 token 回调是可替换的连接点，不代表说明书要求某种认证技术。

接口与类型的唯一实现依据是 `src/services/api/index.js`、`contracts.d.ts` 和同目录 README。本清单按这些文件核对。演示传输层即使兼容旧分页别名，正式接口仍使用 cursor/limit；这不等于要求后端也实现旧别名。实体记录通常包含 `id`、`revision`、`createdAt`、`updatedAt`。revision 以未加引号的字符串传给 options，请求层负责生成 `If-Match: "revision"`。

成功示例：

```json
{
  "data": {
    "id": "txn_demo_001",
    "businessId": "demo-business",
    "businessDate": "2026-06-15",
    "direction": "outflow",
    "kind": "expense",
    "amountMinor": "12850",
    "currency": "CNY",
    "categoryId": "cat_materials",
    "summary": "原材料采购",
    "status": "posted",
    "categoryStatus": "confirmed",
    "source": { "platform": "manual" },
    "revision": "2",
    "createdAt": "2026-06-15T01:00:00Z",
    "updatedAt": "2026-06-15T01:00:00Z"
  },
  "meta": { "requestId": "req_demo_001", "dataVersion": "7" }
}
```

字段错误示例：

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "请检查录账信息",
    "fieldErrors": { "amountMinor": ["金额必须大于 0"] }
  },
  "meta": { "requestId": "req_demo_002" }
}
```

客户端不在 HTTP 层自动退出登录或弹 Toast。页面/应用层按 ApiError.code、status 决定行为：字段错误放回表单；403 显示权限提示；冲突提示刷新；取消通常不弹错误提示；401 交给统一登录流程。无需把原始异常堆栈展示给经营者。

交易 `kind` 的当前枚举为 sale、expense、refund、transfer、settlement、loan、owner_contribution、other；`direction` 为 inflow/outflow。分类的 metricRole 是另一字段，不能拿它替换交易 kind。指标质量 quality 为 complete/partial/unavailable；上涨下跌用 direction，业务影响用 favorability，两者分开。完整返回保留 envelope，dataVersion 只保证在响应 meta 中出现，不能要求每个 data 实体都重复同名字段。

**MVP 接口对接表。** 下列“返回”均指 envelope 的 data 部分，公共 meta 不重复列出。各方法名以 `src/services/api/README.md` 和实际导出为准。

| 模块/操作 | 前端提交 | 队友返回 | 前端行为与需要覆盖的异常 |
| --- | --- | --- | --- |
| 登录/会话/退出 | `auth.login({ provider, code, redirectUri? })`；`me()`、`session()`、`logout()` | me 返回 `{ id, displayName, businessIds, permissions }`；session/login 返回 `{ user, expiresAt, accessToken? }`；退出为 null | 登录提供商待团队确定；能力声明从主体资料另取，不能假设 me 已含 |
| 主体资料创建/读取/修改 | `{ name, industry, currency, timezone }`；创建带幂等键，修改带 revision | BusinessProfile：id、资料、revision，以及可选 capabilities、supportedImportFormats、supportedExportFormats | 初始化与基础设置；版本冲突、字段错误 |
| 流水列表/详情 | startDate/endDate、direction、kind、categoryId、importId、status、search、sort、cursor/limit | `{ items, nextCursor, total? }` 或单条 Transaction，含 source 与可选 receiptId | 筛选、分页、详情、空态；额外来源筛选字段需先扩展契约 |
| 新增流水 | businessDate、direction、kind、amountMinor、currency、categoryId、summary；可选 note、productId、receiptId、originalTransactionId；幂等键 | Transaction；新数据版本位于 meta.dataVersion | 提交中禁用重复保存，成功刷新相关查询；错误保留输入 |
| 编辑/作废 | id、变更字段或 `{ reason }`、revision；作废另带幂等键 | 更新后的 Transaction 和 revision；版本在 meta.dataVersion | 更新列表，冲突时核对；作废保留历史来源 |
| 批量分类 | `{ items: [{ id, revision }], categoryId }` 与幂等键 | `{ items: [{ id, status: 'updated'/'failed', error? }] }`；meta.dataVersion | 显示选中范围，逐项定位失败；不是仅传 transactionIds，也不是导入用的 rows |
| 分类维护 | name、parentId 可选、direction、metricRole；修改带 revision，归档按独立动作调用 | Category 或分类分页；状态为 archived | 选择器和维护表单；归档已使用分类的处理由后端定义 |
| 商品/服务维护 | name、sku 可选、priceMinor、costMinor、currency；修改带 revision | Product 或商品分页，含 archived | 当前返回契约没有正式商品毛利字段；不扩成进销存，实际期间利润仍需销售与成本数据 |
| 成本归集 | name、categoryId、amountMinor、currency、periodStart/periodEnd；可选 sourceTransactionId、note；修改带 revision | CostAllocation，status 为 active/voided | 显示来源交易；不得把成本项与同一支出再次相加 |
| 导入文件/读取批次 | `imports.create(FormData)`：file、platform，可选 sourceAccountId；`imports.get(importId)` | ImportBatch 的 id 即 importId，另含 status、可选 jobId、filename、platform、parserVersion、counts | 批次自身不返回 phase/progress；如果有 jobId，再查 jobs.get 获取 stage/progress |
| 字段映射 | importId、`{ columns, dateFormat?, encoding? }`、批次 revision；columns 统一为源列 → 目标字段，例如 `{ "金额": "amountMinor" }` | 更新后的 ImportBatch 与解析状态 | 按当前 IngestionView 的实际提交方向对接；后端按此实现，演示兼容双向不代表正式接口必须兼容 |
| 导入行预览/修正 | importId、cursor/limit、状态筛选；`updateRow(importId, rowId, { draft?, categoryConfirmed?, kindConfirmed?, duplicateDecision? }, { revision })` | ImportRow 分页或单行：raw、draft（含 kind 与可选 originalTransactionId）、status、reviewReasons?、categoryConfidence、fieldErrors、duplicateTransactionId? | 每页最多 100 行，只有本页明确勾选且 ready 的行可提交；转账/退款/不明用途先核对 kind，退款关联原流水；重复与待确认不自动入账 |
| 确认导入/取消 | `commit(importId, { rows: [{ id, revision }] }, { idempotencyKey, revision })`；cancel(importId, { idempotencyKey }) | commit 返回 Job，其 result 为 `{ importId, postedTransactionIds, failedRowIds, pendingRowIds }`；取消返回 ImportBatch | 不采用模糊的“全部确认”选择规则；任务完成后核对每行，取消方法当前不接收原因 payload |
| 导入历史 | imports.list(query)：cursor/limit 与双方确认的批次过滤条件 | ImportBatch 分页，含 counts、createdAt/updatedAt | counts 为 total、invalid、duplicate、ready、needsReview、posted；不把分类成功当作入账 |
| 指标总览 | AnalyticsQuery：startDate/endDate、timezone、granularity；可选 metricBasis、比较条件、dataVersion/snapshotId | `{ query, metrics }`；Metric 含 id、label、value、unit、definition、quality、qualityReason?、evidenceId? | 比较值从 comparisons 单独取；版本在公共 meta，KPI 不写死截图数字 |
| 趋势 | 同一 AnalyticsQuery，granularity 为 day/week/month | TrendSeries[]：metricId、unit、points[{ date, value, evidenceId? }] | 值可空，日期桶由后端生成；当前无独立指标 IDs 请求字段 |
| 同比环比 | comparison 为 previous_period/previous_year/custom；自定义用 compareStartDate/compareEndDate | Comparison[]：current、previous、absoluteChange、relativeChange、percentagePointChange、direction、favorability、unavailableReason? | 截至同日通过明确日期区间表达；基期为零/负和缺失数据按后端口径处理 |
| 成本结构 | 同一 AnalyticsQuery，可选 categoryId、metricBasis | `{ denominatorMetricId, totalMinor, items: [{ categoryId, label, amountMinor, ratio, evidenceId? }] }` | 分母由响应明确，不把分组占比默认解释为成本/收入；下钻复用查询范围和分类 |
| 查询证据 | `analytics.evidence(evidenceId, { cursor?, limit? })` | `{ id, snapshotId, dataVersion, query, metrics, transactions: Page<Transaction> }` | 从 evidenceId 取快照；计算时间仅在服务端实际返回 meta.generatedAt 时展示 |
| 会话创建/历史 | `createConversation({ query, title? })`；`conversations({ cursor?, limit? })`；messages(conversationId, query) | Conversation 或分页，含 title、query；消息列表返回 AssistantMessage 分页 | 不假设会话本身含消息摘要；切换会话，保留范围和主体隔离 |
| 发问/追问 | `sendMessage(conversationId, { text, query, parentMessageId? }, { idempotencyKey })` | AssistantMessage；主键是 id，含处理 status、可选 jobId、metricIds/evidenceIds、querySnapshot | 需要澄清与数据不足是业务状态；模型计算与解释由队友完成 |
| 问答结果/停止 | `getMessage(conversationId, messageId)`；cancelMessage 另带幂等键 | 当前 AssistantMessage；停止状态为 stopped | 初期轮询消息实体；通用任务用 jobs.get；HTTP 取消和停止后台任务分开 |

导入批次 status 为 queued/parsing/review/committing/completed/failed/cancelled；行 status 为 invalid/duplicate/ready/needs_review/posted。批次数量字段使用 needsReview，行枚举使用 needs_review，按契约区分。导入提交可能立即返回终态 Job，也可能先 queued/running，前端都应检查状态；只有 succeeded 才读取最终 result，且仍需处理 failedRowIds，而不是把任务成功等同于每行成功。

**问答结果不能只有一个 text。** 当前基础契约是 `AssistantMessage`，其状态与通用 Job 不同：`queued/querying/calculating/generating/completed/needs_clarification/insufficient_data/stopped/failed`。不要把任务的 succeeded/cancelled 或另一套 phase/outcome 直接当作消息状态。基础消息包含以下内容：

```ts
import type { AssistantMessage, MetricUnit } from '../src/services/api/contracts'

// AssistantMessage 已声明 id/revision/createdAt/updatedAt、role、conversationId、
// status、text、querySnapshot、metricIds、evidenceIds，以及可选的
// jobId、snapshotId、dataVersion、error。
// 下列是当前 UI/demo 兼容的可选展示扩展，尚不是 contracts.d.ts 的必填返回字段。
type AnswerView = AssistantMessage & {
  facts?: Array<{
    metricId: string
    label: string
    currentValue: string | null
    previousValue?: string | null
    unit: MetricUnit
    evidenceId: string
  }>
  suggestions?: Array<{ text: string; supportingEvidenceIds: string[] }>
  actions?: Array<{
    type: 'view_transactions' | 'compare_period' | 'ask_followup'
    label: string
    payload: Record<string, unknown>
  }>
  limitations?: string[]
}
```

当前 UI 可展示可选 facts、limitations 和白名单 actions；suggestions 已由 demo 返回但当前视图没有独立建议卡。即使没有这些扩展字段，前端仍可用 text、metricIds、evidenceIds 展示回答并查询计算依据。证据明细通过 `analytics.evidence` 独立获取，返回 query、metrics、transactions、snapshotId、dataVersion，不要求每条消息另附一套 evidence 数组。后端保证正式数值；解释文字里的现实原因要区分事实与推测。工具编排、模型 key、提示词和 SQL 不进入前端。action.type 由前端白名单执行，不执行后端或模型给出的任意脚本/URL。

数据更新后，旧回答保留其快照并提供重新分析入口。缺少商品销量或客户数据时，在 text 或可选 limitations 明确不能证实的结论。当前问答动作白名单不包含 export_report；报告导出需要单独接通 exports 服务、能力声明和相应界面后再扩展。

报告未指定微信通知渠道、每日增量备份、加密导出或固定角色名。前端可保留配置和显示位置，但需按后端返回的 capabilities 决定是否启用。Excel/PDF 是参考图中的导出格式建议，由主体返回的 supportedExportFormats 决定；不能把未实现的加密声明写成固定安全文案。Receipt.status 为 queued/recognizing/review/committing/posted/failed；通知状态为 not_configured/queued/delivered/failed，不可自行改成“已推送微信”。

**建议能力声明。** 当前契约统一由 `business.getProfile()` 返回可选 capabilities，`auth.me()` 返回身份、businessIds 和 permissions。格式数组是 BusinessProfile 的顶层字段，应用初始化层将它们映射为页面使用的能力状态。名称是草案，不是强制数据库字段；以下是主体响应 data 中与能力有关的片段：

```json
{
  "capabilities": {
    "billImport": true,
    "analytics": true,
    "assistant": true,
    "ocr": false,
    "alerts": false,
    "memberManagement": false,
    "backup": false,
    "export": false
  },
  "supportedImportFormats": ["csv"],
  "supportedExportFormats": []
}
```

这里的 false 表示尚未开放或主体不可用；权限另有单独判断。缺失能力或格式数组也不能推断全部开放。supportedImportFormats 使用不带点的扩展名，supportedExportFormats 当前是 xlsx/pdf 的子集。能力关闭时可以隐藏操作或标“暂未开放”，不点击后伪造成功。接口调用层仍保留对应方法，后续队友启用能力时不用重写组件结构。当前 demo 的扩展路径返回 501/FEATURE_NOT_AVAILABLE，表示明确未实现，并非演示成功。

**每项接口如何交接。** 在团队的接口文档或任务卡中逐项记录，避免只给一个 URL 就开始联调：

| 字段 | 队友需确认内容 |
| --- | --- |
| 功能与阶段 | 对应说明书章节；MVP 或扩展 |
| 负责人 | 前端负责人、后端负责人 |
| 前端入口 | 页面路由、组件、领域 API 方法 |
| 传输约定 | HTTP 方法与路径，或云函数名和适配关系 |
| 请求 | 必填/可选字段、类型、枚举、金额/日期单位、示例 |
| 成功返回 | 完整 data/meta 示例；空数据与部分数据示例 |
| 错误返回 | 字段错误、权限、冲突、限流与业务失败示例 |
| 长任务 | 创建返回、状态查询、阶段、进度、取消能力、结果保留期 |
| 幂等与版本 | 哪些写入需要 key、冲突状态码、revision 格式 |
| 联调环境 | baseUrl、鉴权方式、测试主体、示例数据版本 |
| 当前状态 | 待确认 / Mock 可用 / 后端就绪 / 联调中 / 已验收 |
| 验收 | 操作步骤、期望界面、对应结果与 requestId |

前端自测与共同验收分开记录。前端请求封装的测试只能证明请求参数、响应转换和异常处理正确，不能证明队友已经实现可靠去重、权限隔离或正确财务口径。

**跨页面刷新约定。** 新增/修改/作废流水、确认导入、确认 OCR 后，以响应 meta.dataVersion 为依据，使相应流水、成本、指标与预警查询失效。重新请求当前显示范围；快速切换期间和经营主体时取消或忽略旧响应。历史 AI 消息保存原快照，重新分析才生成新答案。

预览不触发正式指标刷新；前端点击保存但请求尚未成功时不显示“已入账”。写请求超时后先根据已有任务 ID 或复用幂等键核查结果，不能简单认为失败后新建一笔。

**联调最先通过的业务链。** 登录并取得主体 → 手工录入一笔 → 列表可查 → 指标变化 → 询问变化原因 → 回答引用该指标 → 点击证据回到流水。随后加入账单导入与批量分类，再接 OCR、预警、成员和导出备份。

关键共同验收场景包括：重复提交不重复入账；同日期同金额不同交易不被误删；退款/转账/结算不误算营业额；成本关联不重复计入；上期为零不显示无穷增长率；同一查询所有页面一致；AI 数值有证据；主体权限隔离；OCR 确认前不入账；预警不因重算重复通知；导出与快照一致；备份可以实际恢复。

当前仓库提供的 API 预留层不承诺这些服务端能力已存在。联调状态应由你和队友逐项更新，不能以页面或 Mock 展示成功代替接口验收。
